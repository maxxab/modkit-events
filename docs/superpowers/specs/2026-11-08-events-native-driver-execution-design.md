# Native E14/E28 statement execution

## Selected approach and boundaries

Add one optional `persistence/native_execution.py` issuer using public psycopg 3.3.8 RawCursor and the existing canonical controller. No second controller, pass-through callback executor, generic statement compiler, private wait override or new connection is introduced. Only canonical E14/E28 and an empty ReturnContext are supported. The caller explicitly owns the managed connection and root lifecycle. The issuer never explicitly begins, commits, rolls back, reconnects or physically closes that connection.

Supported profile is the existing cooperative fresh, unpooled ManagedConnection: caller does not change its PGconn, enter nested transaction/savepoint scopes, directly finalize or concurrently use the connection, replace driver methods/adapters, or mutate frozen request objects. Exact class is not proof of those ownership obligations. The executor independently verifies original physical identity, open non-autocommit INTRANS status and pipeline OFF immediately before and after the actual call. Both SQL functions verify actual READ COMMITTED isolation. E14 observes the actual top-level XID; no invented caller identifier is accepted.

The driver may use its standard public interrupt cancellation and emergency closure. Neither means caller rollback, commit acknowledgement, physical-close receipt or replay permission. Received-primary means the exact BaseException received by the package, its cause/context/suppression and received traceback suffix, not an earlier exception replaced inside the driver.

## Interfaces and execution order

- `prepare(execution, statement, parameters, /, *, execution_ledger)` first obtains one construction slot, then reserves a fixed 1024-byte preparation envelope before creating the empty context and raw FrozenRequest. Canonical paid reserve/set/release helpers reuse that same live construction reservation, so preparation works with one slot and cannot leak an unreturned envelope if construction admission fails. The existing public wrappers keep their signatures, guards and one-construction semantics. Native cleanup requires the exact builder token of only its own still-unreturned envelope; it clears request and outgoing references before refund. Known raw/guard failures return codes and are raised only after cleanup and normal construction exit. Unexpected failures, including lost reserve/set acknowledgements or exceptions resembling known error codes, retain construction and envelope backing. No database use.
- `execute(ticket, result, /, *, execution_ledger)` consumes only the exact request returned by `_start_operation(ticket, result, ledger, reservation=paid)`. The caller obtains the ticket from admit(root, preparation), reserves its one empty result first, then invokes this function. The function returns no materialized value; the caller reads the completed paid result through read_result. Recommended result capacities are 64 bytes for E14 and 4 MiB for E28. A smaller capacity can fail after execution and is not retry authority.
- Operation becomes RUNNING before any driver observation/cursor creation. The same canonical atomic transition binds that operation to the exact live issuer reservation, so a duplicate/wrong-result/wrong-ledger attempt cannot claim another issuer's work. A known canonical pre-start rejection with no same-attempt ownership unwinds outside the outer construction frame; it performs no I/O and does not contain the domain. Unexpected lost acknowledgement remains held when the atomic reservation identity proves this attempt started. A charged outer construction frame, represented by a live exact private reservation token bound to its issuing thread, owns actual connection, original PGconn, cursor, PGresult, bounded copied row, decoded row and typed candidate until publication or failure retention.
- Execute exactly the existing fixed descriptor SQL via `psycopg.RawCursor(actual, row_factory=tuple_row).execute(sql, retained_request.parameters, prepare=False, binary=True)`. Before execution, register public built-in BytesBinaryDumper for bytes and ByteaBinaryLoader for every selected binary OID on the cursor-local adapters. Connection/global maps remain unchanged. No row fetch API or application row factory runs. Legitimate selected-OID custom adapters are overridden locally; unexpected protocol OIDs are rejected after execute under the documented unchanged-adapter/migration/endpoint profile, not claimed safe under arbitrary hooks. Empty E14 parameters are still the retained tuple.
- Validate TUPLES_OK, exact field count/name/OID/binary format/fixed width, at most one row (E14 exactly one), command tag/tuple count and cursor rowcount before copying any field. LIMIT 2 provides the overflow sentinel. Then copy/check only cap_ok (one fixed bool byte), and copy the remaining bounded row. Verify no additional result set. Reject every unexpected observation with a fixed code.
- Binary conversion reuses native_codec. E14 extracts its validated scalar; E28 uses `_decode_outbox_raw` for the entire row. Do not call `_decode_event_rows_raw`, whose request revalidation replaces parameters. set_result performs exact retained-type, full raw semantics and event-id coupling validation again without altering request identity.
- Close only the cursor with its public method, check physical postconditions, then set_result and complete known=True. Completion occurs only after the actual synchronous call, row materialization and cursor close have stopped. A completed value is a staged observation, never commit acknowledgement.

## Bounds and public API limits

The pinned public PGresult API has no cell-length-before-copy method. The pre-copy proof therefore consists of the fixed SQL projection's cap checks/CASE nulling, binary built-in OIDs/formats and fixed-width metadata, exact cardinality and a true cap_ok byte. No private libpq pointer API or custom driver is used. Server function/type/schema integrity is the supported migration/bootstrap prerequisite. No promise is made against arbitrary DBA replacement of built-in encoders or the protocol endpoint.

Variable cells total at most 3,150,159 bytes per E28 row; fixed SQL limits returned rows to two and the client rejects two before copying. The typed graph is charged in BB; frozen request graph in AB; bounded driver/cursor/native result/copy/decoder transients and exceptional traceback graphs remain under D construction ownership. These are finite product bounds, not process RSS/native allocator guarantees. Original caller-owned connection state is charged by canonical P/V/C. Escaping unexpected exceptions permanently retain D and contain the domain, as the existing controller specifies.

## Failure, interruption and noninterference

Capture the first BaseException at the immediate package catch, never stringify or log it. Before later reuse, mark HELD/root UNKNOWN through canonical `_fail_operation_paid(ticket, ledger, paid, stopped=...)`. The operation must retain the identical token from its atomic start, and the exact private reservation token must still be live on its issuing thread; it is yielded by `_construction` only after D is charged and invalidated on every context exit. The paid failure transition does not reserve another D or read ledger context before atomically publishing HELD/root UNKNOWN/blocked. Only then does it perform the fallible ledger union. Existing public hooks keep their guards. It accepts RUNNING/HELD and a just-COMPLETED operation when the final completion acknowledgement failed; it never grants release/refund. If original PGconn status is INTRANS, INERROR or IDLE, the issuer reports quiescence to the same paid failure transition, which clears running while retaining HELD. If it remains ACTIVE, becomes UNKNOWN/closed, or observations fail, keep running=True indefinitely. There is no polling, recovery, automatic rollback/close/replay or refund route. Cursor cleanup is attempted only after the public call returns; its failure cannot replace the first exception. A result setter rejection after work follows the same uncertainty rule. Secondary bookkeeping exceptions cannot replace the exact primary. A concurrent hold cannot be converted back to successful completion.

Package diagnostics contain only fixed ErrorCode values, never SQL parameters/rows/DSNs or exception text. Application logging remains untouched. Qualify standard driver interrupt, failed cancellation warning, timeout emergency closure, secondary cleanup/logger failure using nonsecret sentinels. Source injection tests establish package control-flow only; actual driver/DB tests establish selected supported paths separately. A driver-side logger failure received in place of an interrupt is preserved as that received primary.

## Verification and remaining scope

Independent review must approve this design, the exact implementation, pinned driver profile and fresh bounded fixture before any actual driver/DB run. Source tests use explicit structural fakes and do not claim driver outcomes. Driver fault tests may use process-level external signals and isolated fixture faults; never patch private wait/generator code, install dependencies or silence logs. Any exact path that cannot be qualified remains NOT RUN, not a successful guarantee.

Native success covers only E14 same-root XID and E28 bound optional complete row, caller rollback/commit and conservative failure handling. It does not qualify Workers W01-W05, ORM recipes, E10, final grants/manifests, installed artifacts or whole-product readiness.

Selected actual-driver observations cover ordinary interrupt cancellation, failed-cancel warning followed by timeout emergency closure, and an application logger exception replacing the interrupt before the package boundary. Received error links and traceback suffix, sticky uncertainty, unchanged uncommitted business effects and bounded client/server diagnostic sinks are checked separately from source-only fixtures. Natural cursor-close failure remains source-only; cancellation cases do not qualify materialized-payload privacy. Preparation-capacity regressions are a separate pre-admission correction and do not change statement, driver wait or cancellation behavior.
