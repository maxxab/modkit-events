# Bounded publication recovery
E26 implements the existing three-argument outbox scan contract. It counts raw digest identities, including locked and ineligible rows, and returns a header followed by retained changed-row observations in digest order. Reaching either bound reports pass_exhausted=false. True means the raw scan reached the end before both bounds, not that every expired row was recovered.

Under READ COMMITTED it takes a nonblocking row mutex, validates the complete current outbox row, then uses database time. An expired claimed row without an intent becomes pending. An expired publishing row retains its intent and becomes held. No uncertain publication becomes automatically retryable. Token and lease are cleared and ownership revision advances once. Full event/replay material, intent, receipt and outcome evidence are retained. One append-only recovery history records the retained intent, no operation/receipt and empty generated evidence/binding.

Maximum int8 revision is validated and then skipped without mutation/history; max-minus-one can release to max. Exhausted rows remain observable and need separate intervention. A future lease is skipped after complete preimage validation. Integrity failure remains PZ012 even on otherwise ineligible owned rows. Each scan skips locked rows; callers must start another pass to revisit them.

## Verification scope
Source guards cover ABI, least privilege, validation order, bounded keyset scan, nonblocking lock, complete preimage, expiry/revision handling, exact retained postimages and history. The SQL fixture covers public enqueue/claim/intent recovery, stale ownership rejection, all retained fields, both revision boundaries and states, paging, empty/exhausted passes, invalid inputs and semantic corruption.

The fixture requires a disposable PostgreSQL transaction and explicit authorized owner. It is not a deployment script. The corrected fixture passed a bounded PostgreSQL18.1 check, including input/isolation rejection, access controls and one real overlapping two-session lock-skip schedule. The holder recovered the first row while the contender skipped its uncommitted lock, counted both raw identities and recovered the second row; each wrote exactly one recovery history. Fourteen source guards and the available base suite passed. Optional Pydantic was unavailable and excluded; optional backend skips are not qualification. Production grants, manifest and package readiness are unchanged. No E10, native driver, full migration, physical I/O, all concurrency schedules, exact clock-equality or release qualification is implied. Commit acknowledgement and external outcome evidence remain application-owned.
